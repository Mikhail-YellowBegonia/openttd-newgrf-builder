# 开发路线图

本文记录 2026 年 9 月 25 日开始的新一轮开发计划。目标日期是内部工作目标，是否发布以构建、游戏内测试和素材权利审查全部通过为准。

## 项目目标

- 面向 OpenTTD 的中国建筑 NewGRF，覆盖乡村、城镇与城市的不同密度层级。
- 按建筑年代控制出现时间、替换与演化，形成可信的中国聚落景观。
- 以 32bpp zi4 母版为主要交付格式，normal/zi2 由最近邻派生，保留可重复生成的高质量源素材。
- 使用实景参考约束 AI 图像生成，并保存来源、提示词、模型和人工修改记录。
- 建立从素材输入、透视与光照统一、切图、校验到 `.grf` 输出的自动化流水线。

## 工作流阶段

### 1. 调研与构建基线

1. 记录 NewGRF House 的 Action 0 属性、Action 1 精灵组、Action 2 图形逻辑与 Action 3 映射关系。
2. 核对 32bpp extra zoom 精灵的文件、偏移、透明与缩放约束。
3. 固化 Python、NML 和一键构建入口；VOX/GoRender 与 grf-py 仅保留为历史原型资料。
4. 为每个建筑建立稳定 ID、年代、密度、占地和来源元数据。

### 2. 原型制作

1. 组织等距风格参考、建筑内容参考和可选手绘草图。
2. 人工操控生成模型，优先验证体块、屋顶、立面和遮挡关系。
3. 选择少量建筑走完“参考图板、生成、清理、zi4 落位、标准化、游戏内验证”全流程。
4. 记录每一步的人工时间和失败类型，作为自动化优先级依据。

### 3. 标准化与批量生产

1. 以 `assets/manifest.csv` 作为素材任务和溯源的单一入口，并区分风格参考、建筑参考和草图。
2. 将生成、抠图、透视校正、调色、阴影、画布与偏移检查拆成可缓存步骤。
3. 并行执行互不依赖的建筑任务，但对模型、提示词模板和后处理版本做锁定。
4. 构建阶段拒绝缺少来源、年代、密度、授权状态或质量检查结果的素材。

## 建筑分类初稿

密度先采用 `rural`、`town`、`urban`、`highrise` 四级；年代先采用 `pre_1949`、`1949_1978`、`1979_2000`、`post_2000` 四段。调研完成后再依据 OpenTTD 的生成机制和素材分布调整，避免过早锁死分类。

## 支线：邻接适配

在不阻塞首版的前提下，建立 Action 2 / VarAction2 实验：读取相邻 tile 的 house class、GRF ID 或连续建筑信息，选择边墙、转角、端头或中段图形。实验结果见 `research/adjacency.md`。

## 工作台后续计划

本轮先提供常备参考图选择、登记素材只读总览和更小的抠图锚点。下列项目保留在后续迭代，完成前保持现有人工审核和文件落盘流程。

1. **网格参考资产矩阵**：按 `1x1`、`1x2`、`2x1`、`2x2` 和一般、高、超高建立 12 个稳定资产 ID；每张图记录模板、画布、锚点、投影和生成用途。当前已接入 Temporal8 `1x1·一般`，其余位置逐张补齐。
2. **建筑素材总览与 ID 管理**：从 manifest 和登记库生成可搜索的建筑目录，显示缩略图、建筑 ID、House ID、占地、年代、密度、来源和 QA 状态；新增建筑时提供命名校验和空闲 House ID 建议。缩略图按 alpha 非透明区域生成边界框，保留原图路径供追溯。
3. **固定网格自动抠图实验**：对空网格底图与输入图做颜色容差、魔棒 flood fill 和 XOR mask 对比，记录网格线、阴影和半透明边缘的误差；验证通过后再提供初筛 mask，人工 mask 仍作为最终结果。
4. **临时卡片相册**：在侧边栏提供不持久化的图片卡片，支持工作区与相册拖拽；允许把实景参考、网格参考和 AI 多结果组合后送入外部生成服务，再把选中的结果放回相册继续处理。刷新页面或关闭工单时清空。
5. **多 tile 与 object 资产**：扩展 `1x2`、`2x1`、更大 footprint 和 object 类素材的模板、锚点与切片检查，验证 offset 由几何和挂接点语义推导，避免为每个尺寸增加固定补丁。
